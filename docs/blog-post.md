# 第一次用 Java 写后端：我把「请求怎么走一圈」重做了一遍

> 2026-11-20 · 项目 5 复盘 · SpringBoot / MyBatis / JWT / 缓存 / Vue 3

前四个项目我都是用 Python + Django 写的：校园二手交易平台、订单通知幂等、大文件分片上传、接口自动化回归。写得越久越容易形成一种错觉——好像「后端」就长 Django 那个样子：`urls.py` 配路由，`views.py` 写函数，`models.py` 定义表，完事。

所以轮到计划里的 Java 方向时，我其实有点虚。SpringBoot、MyBatis、IoC、Bean 这些词我都能背，但没真正从零搭过一次。这篇文章记录的是：我怎么用两周计划里的第 5 个项目，把这套东西从「听说过」变成「能讲清楚」，以及中间被什么卡住过。

先给结论，省得读到最后才发现是一篇流水账：**Django 和 SpringBoot 不是两套东西，是同一套骨架换了名字。** 都是「浏览器发请求 → 安检 → 路由 → 视图 → 模型 → 数据库」，只不过 Java 这边把每一层都拆得更细、更显式。

---

## 一、第一关居然是「跑起来」

我原以为写代码最难，结果第一天全花在环境上。

我用 `java -version` 查，提示没这个命令；但 `JAVA_HOME` 明明指向 `D:\jdk-26.0.2.1`，C 盘还躺着一个 `jdk-17`。原来这两个 JDK 都在，只是没进 PATH。用完整路径调用就行了，不是什么大问题，但足够让一个新手怀疑人生半小时。

Maven 是真没装。按「尽量避免折腾环境」的原则，我没有往系统里装，而是下载了 9MB 的 zip 解压到项目里的 `tools/`，再用 `start.py` 统一调它。好处是仓库里不放二进制、换台机器 clone 下来一条命令能复原；坏处是第一次要等下载。这个取舍我很喜欢：**环境改动留在项目内，不污染系统。**

然后第一次 `java -jar`，直接起不来，日志刷了三屏。最上面是 `BeanCreationException`，一层层 `Caused by` 翻到最底下才看到真凶：

```
Feature not supported: "AUTO_SERVER=TRUE && DB_CLOSE_ON_EXIT=FALSE" [50100-224]
```

H2 不允许这两个参数同时开。`AUTO_SERVER` 是给多个 JVM 共享同一个数据库文件用的，我单进程根本不需要，删掉即可。这里学到一个很实用的习惯：**Spring 的报错要倒着读，最上面那串通常只是「谁被连累了」，最底下那句才是起因。**

改完又遇到一件更隐蔽的事：日志里 Tomcat 起在 53555，不是我配的 8003。`env` 一查，宿主环境注入了 `SERVER__PORT=53555`，SpringBoot 的宽松绑定把它认成了 `server.port`，优先级比 `application.yml` 高。最后我在启动命令里显式加了 `--server.port=8003`（命令行参数优先级最高），才算彻底定死。

这两件事都不难，但都是「不看日志就永远猜不到」的类型。我把它们写进了技术文档的踩坑复盘，因为它们比代码本身更像真实工作。

## 二、把 Django 的零件换成 Java 的名字

环境通了，我开始对着骨架做翻译：

| 我熟悉的 Django | 这次的 Java | 其实都在干一件事 |
|---|---|---|
| `urls.py` | `@GetMapping` / `@PostMapping` | 把 URL 指到某个方法 |
| `views.py` | `@RestController` | 收请求、返 JSON |
| 手写业务逻辑 | `@Service` | 规则集中在一层 |
| ORM / `Model.objects` | MyBatis `Mapper` 接口 | 对象 ↔ 表行 |
| `models.py` | `entity/` 下的 POJO | 数据长什么样 |
| Middleware | `HandlerInterceptor` | 请求进来前统一拦一道 |
| `JsonResponse` | `ApiResult<T>` + Jackson | 统一响应外壳 |
| Session 登录 | JWT | 确认「你是谁」 |

真动手才发现，Java 这边「分三层」不是形式主义。比如发布一篇文章：Controller 只有一行 `return ApiResult.ok(service.publish(id))`；Service 里校验文章是否存在、改状态、写 `published_at`、**清缓存**；Mapper 里只有一条 `UPDATE`。

好处在改需求时特别明显：后来我想给「发布」加缓存失效，只改了 Service 一处，Controller 一行没动。如果全塞在一个函数里，就得满屋子找「还有哪个入口也改了库」。

MyBatis 的 `<script>` 一开始看着吓人：

```xml
<where>
  <if test='status != null'> AND a.status = #{status} </if>
  <if test='kw != null'> AND LOWER(a.title) LIKE ... </if>
</where>
```

后来想通了——**它不是魔法，就是按条件拼字符串**，`<where>` 帮忙去掉第一个多余的 `AND`，`#{}` 交给 JDBC 做参数绑定（所以不是字符串拼接，不会被注入）。Service 里把空字符串统一转成 `null`，`<if>` 就只用判断 `!= null`，连 OGNL 引号嵌套的坑都绕开了。

## 三、JWT：手搓一遍才真的懂

登录这块我本来可以直接引 `jjwt`，一行依赖搞定。但我选了用 JDK 自带的 `Mac` 手搓 HMAC-SHA256，因为我想搞清楚那三段到底是什么。

写完才发现，JWT 简单得有点反直觉：

```
头.载荷.签名
```

头和载荷只是 Base64Url 编码，**谁都能解开看**，里面就是 `{"uid":1,"exp":...}` 这种明文。真正防篡改的是第三段：用只有服务器知道的密钥，对「头.载荷」算一次 HMAC，再把结果附上。校验时重新算一遍，用 `MessageDigest.isEqual()` 做常量时间比较（避免攻击者靠响应时间一点点猜签名），再看看 `exp` 过没过期。

所以「JWT 不需要在服务器存登录状态」这句话一下就具体了：服务器不记你，只认钢印。代价也随之而来——签出去的 token 在过期前不好单独作废，所以有效期要短，敏感操作要二次校验。

这里也埋了一个真实的 bug。我的安检口规则是「读接口公开，写接口要 token」，结果 `/api/auth/me/` 是 GET，被一起放行了：拦截器压根没验，也没把 `userId` 塞进请求，Controller 只能无奈地返回「请先登录」。23 条端到端回归里挂了 3 条，一眼就定位到 `needToken()` 的判断顺序。加了「`/api/auth/me` 无论什么方法都要验」这条例外，全绿。

**写测试最大的价值不是证明代码对，而是把这种「看起来合理、其实漏了」的地方逼出来。**

顺带说清边界：密码我用的是带固定盐的 SHA-256，密钥写在配置文件里，也没有 refresh token 和黑名单。这些在教学项目里够用，但要上线必须换 BCrypt、环境变量注入密钥、加退出即失效。我在技术文档里专门列了「离生产还差什么」一张表，还写了「任意登录用户可改他人文章」这个已知缺口 —— 能主动讲清边界，比假装没有边界更专业。

## 四、缓存不是一个 Map 那么简单

计划里写的是 Redis，但这台机器没装 Redis。我没有跳过这部分，而是做成了**双后端**：启动探测一次，能连上就用 Redis，连不上自动回退 JVM 内存；页面右上角明确标出当前用的是哪个；运行中 Redis 挂了也会自动降级。

理由是：缓存的逻辑（什么时候读、什么时候写、什么时候失效）跟「用 Redis 还是用内存」其实是两件事，不该绑死。

真正费心思的是「失效」。`ArticleService` 里每次新建、修改、发布、删除，都要调 `invalidate()` 清掉三类 key：列表、这篇文章的详情、这篇文章的评论。少清一个，页面就会一直显示旧内容——这是缓存最经典也最容易被忽略的 bug。于是我干脆把每一次 `HIT / MISS / WRITE / EVICT` 都写进一张 `cache_event` 表，看板上直接画成时间线。

第一次读分类：MISS → 回源 → WRITE；第二次：HIT。发布文章之后：EVICT → 再读又变 MISS。**这几行流水比任何文字解释都直观**，我后来给它配了「一键跑完整流程」按钮，13 步真实 HTTP 请求按次序发，把这个节奏完整演一遍。

还有个小优化挺有意思：没有 Redis 时，每次探测都要等一次连接超时，而 `/api/demo/state/` 会调两次，页面明显卡顿。给探测结果加了 5 秒缓存，只在手动切换后端时强制重探。这种「不改功能、只改体感」的修法，很值得记下来。

## 五、把内部动作摊开给人看

前四个项目我都配了可视化看板，这次延续了下来。原因很私人：**我自己就是靠看板才把原理想明白的。**

看板上有 6 张统计卡、一张四层架构流程图、13 步演示步骤、缓存事件时间线和 API 请求流水。所有数字都来自 `GET /api/demo/state/` 这个聚合接口 —— 真实项目里前端会分别调五六个接口，演示项目为了「一眼看全」在服务端拼成一个大包裹，这有个正经名字叫 BFF（给前端定制的聚合层）。

前端用本地 Vue 3，不引 CDN，断网也能打开。`app.js` 里所有请求走同一个 `request()`，自动带 `Authorization` 头，统一解析 `{code, message, data}`。数据一变，页面自己重绘，整页不刷新。

加 `?demo=1` 自动跑演示，本来是为了用无头浏览器验证按钮真的能点，后来发现它还是个挺好用的分享链接。实测 13 步全部渲染，12 个 200 加 1 个预期中的 401，演示创建的文章最后自动删掉，数据回到 8 篇。

## 六、三层测试，各管一段

这次的验证分了三层，各有各的存在理由：

- **11 个 JUnit 5 + MockMvc**：在进程内模拟 HTTP，不起端口、用独立内存库，验证上下文能起、JWT 校验、CRUD 生命周期、缓存 HIT。
- **23 条 Python 端到端回归**：真的走网络、真的写库、真的读回来，验证 JSON 序列化、拦截器写出的真实 401、删除后 404、重置。
- **无头浏览器 + `?demo=1`**：验证 Vue 挂载、fetch 真的发出去、DOM 真的更新，桌面和 500px 手机端各截一张图。

三个数字：`Tests run: 11, Failures: 0`、`23 条 / 23 通过 / 0 失败`、13 步浏览器演示全渲染。

这里又复用了一个跨项目的经验：机器上有全局 `HTTP_PROXY`，Python 的 `urllib` 默认会走代理，把 `127.0.0.1` 的请求也转发出去，拿回来的是代理的 404 而不是自家接口。项目 4 为这个折腾过一次，这次我在 `e2e_api.py` 里一开始就写了 `ProxyHandler({})`，`curl` 验证也一律加 `--noproxy '*'`。坑写进文档，下次才不用再踩一遍。

## 七、写在最后

这个项目做完，我最踏实的变化不是「会写 SpringBoot 了」，而是：再看到任何后端项目，我脑子里先出现的是那条固定链路——**谁接请求、谁定规则、谁翻译 SQL、谁存数据、哪一步可以抄近路（缓存）、哪一步必须验身份（安检口）**。框架只是把这条链路上的零件换了个名字。

按两周计划，Java 方向先做了博客系统，因为它和前四个 Web 项目能连成一条线：交易 → 消息可靠性 → 文件上传 → 接口测试 → 换语言重做同一套骨架。简历上摆出来，是一条「从业务功能到工程质量、再到跨语言迁移」的路线，而不是五个互不相干的小 demo。

剩下还没做的，我都不打算藏：真 MySQL、BCrypt、JWT 黑名单、文章归属校验、深分页优化。技术文档第 15 节列成了一张表。下次有人问「你这个项目能上线吗」，我希望自己的回答是「哪些能、哪些还差、为什么先不做」，而不是一句含糊的「差不多吧」。

从 Python 转过来，我觉得别急着背注解，先找一条最简单的请求从头到尾跟一遍。跟完一遍，`@RestController`、`@Service`、`@MapperScan` 这些词自己就长到场景里去了。
